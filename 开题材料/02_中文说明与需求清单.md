## 研究如何讲清楚

对象是接触网规范查阅。用户输入自然语言问题，系统查找知识库证据，再生成能够追溯出处的答案。研究重点是：混合检索是否改善召回、标准版本处理是否减少误引用、证据检查是否减少无依据回答。它们都是待检验的问题，不能提前写成“显著提高”。

现有代码提供基线，不把 BM25、RAG 或调用在线 API 本身宣称为原创算法。计划中的个人工作包括规范子集整理、版本处理、证据检查、评测集建设、消融实验和失败原因分析。写作时区分“参考实现已有”“自己计划改进”“实际验证完成”。

## 草案中的量化目标

20–30 份可用去重文档、100 道人工核查问题（20 开发 / 80 测试）是计划规模。Recall@5 ≥ 0.80、答案正确率 ≥ 0.80、引用支撑率 ≥ 0.90、拒答召回率 ≥ 0.80、误拒答率 ≤ 0.10 是**拟议目标**，并非数据、学校硬性指标或性能保证。指标定义见实验方案；提交开题时与导师讨论其合理性，之后任何修改均需留痕。

参考实现已通过离线自检；独立新系统已完成真实 DeepSeek 联调并能展示规范问答。向量服务和正式评测尚待完成。25 份候选中只有 14 份在抽样规则下提取较好；最终选用 20–30 份还需补选、去重和人工复核。其余文件不能因已有文本版候选就忽略记录。
