## 第一部分：项目描述

### 研究背景与问题

接触网规范包含专业术语、数值要求、适用条件和不同年份版本。现有资料分散在 PDF、DOCX 等文件中，查阅者不仅需要找到相关条文，还需要核对答案适用的标准、版本、单位和条件。语言流畅但缺乏原文支持的回答，尤其是引用错误版本的回答，可能误导学习和工程资料查阅。

检索增强生成（RAG）将证据检索与语言生成结合[1]。BM25 适合根据字面关键词检索[2]，稠密向量检索提供基于语义表示的另一条路线[3]。但是，采用这些方法本身不能保证版本正确，也不能保证每条回答都被原文充分支持。因此，本课题研究的重点是证据可追溯性与回答可靠性，而不是单纯接入大模型。

查询改写研究[4]为检索前理解追问提供设计参考；首版采用明确的上下文规则，不训练重写模型。无关上下文研究[5]提示需要测试干扰证据，但其算术任务结论不能直接当作接触网规范问答的效果证据。RAGAs[6]提出从多个维度评价检索与生成，本课题据此分别检查检索质量和答案质量，并以人工原文核验作为答案评分依据。

### 总体目标与研究问题

总体目标是构建并评价一个面向中文接触网规范子集的智能问答系统，使其能够检索条文、生成有依据的回答、展示来源，并在证据或指定版本不足时明确说明。

- RQ1：混合检索能否比仅 BM25、仅向量检索提高证据召回效果？
- RQ2：明确处理标准号和年份，能否减少不同版本之间的错误引用与回答？
- RQ3：检索证据检查能否减少无依据回答，同时避免过多拒答？

### 具体目标与可检验标准

| 目标 | 计划期限 | 交付与验收标准 |

拟议性能目标为 Recall@5 ≥ 0.80、答案正确率 ≥ 0.80、引用支撑率 ≥ 0.90、不可回答问题的拒答召回率 ≥ 0.80、可回答问题的误拒答率 ≤ 0.10。这些是开题阶段的工程目标，不是学校规定、已经测得的结果或性能承诺。需报告样本量、差值、不确定性和未达标原因，保留负面结果。API 错误不能算正确拒答。

### 技术路线与系统接口

建库流程：解析 PDF/DOCX → 保留来源位置与版本元数据 → 文本切块 → SQLite 存储 → 对允许在线处理的片段调用独立 Embedding 服务生成向量。

问答流程：用户问题与简单追问上下文 → 标准号/年份约束 → BM25 与向量余弦相似度检索 → 分数归一化及加权融合 → 检索证据检查 → 将获准外传的片段交给 DeepSeek → 校验 JSON、引用编号和逐字摘录 → 展示答案、来源及耗时。

模块之间传递片段文本、稳定标识、来源位置、检索分数、回答状态和耗时。Streamlit 本地界面与批量评测入口共用问答链路。逐字摘录匹配只能证明引用原文存在，不能自动证明整句回答在语义上被充分支持，因此仍需人工判分。

### 可行性、贡献与范围

截至 2026-10-13，已有三份文档的初步知识库，BM25 检索和 DeepSeek 带引用回答能够运行，真实 API 联调已通过。Embedding 接口联调、完整规范子集和正式评测尚未完成。现有演示证明基础流程可行，不代表准确率已经达到目标。

原始参考代码保存在“毕设资料/01_主要代码”，当前实现位于“project/qa_system”。沿用 RAG、BM25 与向量融合思路，如实说明参考代码及 AI 辅助。计划中的主要工作为语料整理、标准版本处理、证据检查、评测设计和结果分析，不把通用算法或调用 API 本身作为原创成果。

首版不开展基础模型训练、图纸理解、OCR 开发、多用户权限及生产部署。系统用于学习和规范查阅，不用于批准工程合规。需要继续学习的内容包括解析质量、检索参数校准、人工标注一致性及 API 成本估算，通过文献阅读、开发集试验和书面评分规则解决。

### 实验实施说明

以下为与英文目标配套的操作细则，不是已完成结果。完整字段与评分公式见“03_实验与验收方案.md”。

| 配置 | 检索方式 | 版本过滤 | 检索证据门槛 | 回答与引用格式校验 |
| --- | --- | --- | --- | --- |
| B1 | BM25 | 开 | 开 | 保留 |
| B2 | 向量 | 开 | 开 | 保留 |
| B3 | 混合 | 开 | 开 | 保留 |
| A1 | 混合 | 关 | 开 | 保留 |
| A2 | 混合 | 开 | 关 | 保留 |

五组固定同一语料、切块、Top-K=5、生成模型、提示词和评分规则。A2 的消融只关闭检索阶段的证据门槛，不关闭模型指令、引用校验或异常处理，因此结论仅适用于该门槛的增量作用。

100 题中计划有 80 道可回答题、20 道不可回答题；开发集分别 16/4 道，测试集分别 64/16 道。最终比较使用固定 80 道测试题。追问上下文作为输入保存；实际计分单位是一条问题，同源条文及同义改写按组划分。

Recall@5 按每题前五条检索结果覆盖的人工证据单元比例宏平均；MRR@5 为首条正确证据排名倒数的平均值。答案正确率以全部可回答题为分母，错误、空答案、误拒答和 API 失败均不计正确。引用支撑率人工检查事实断言与所引证据是否对应，同时报告引用覆盖率。拒答召回率以不可回答题为分母，误拒答率以可回答题为分母。另报错版本率、回答覆盖率、失败类型、延迟中位数和 P95，不能通过全部拒答或删除失败题获得高分。

冻结后保留逐题输出及数据/配置哈希。配对比较按同源问题组估计不确定性；人工判分隐藏配置标签并保留理由。拟保留至少三个成功和三个失败案例，解释检索错误、版本问题、条件遗漏及引用不足等原因。

## 第四部分：职业实践、风险与合规

### 社会影响、包容性与环境

预期用途是帮助查找和核对规范原文。错误版本、数字错误及条件遗漏是主要不利影响，因此展示证据和版本、明确证据不足，并保留人工核查入口。不宣称已经提升生产效率或降低真实工程事故。

界面采用清晰中文标签、可复制原文、键盘可操作控件，以及不只依靠颜色的状态提示。题集覆盖专业术语和普通表达。首轮研究不声称已覆盖英文问答或达到所有无障碍要求。

复用现有硬件、不训练大模型、缓存向量、限制无必要的重复请求。记录调用量和 token 作为资源消耗线索，不在没有测量方法时换算碳减排。保留配置与文档，降低维护和重复建库成本。

### 伦理与工作归属

计划使用技术文档和研究者编写的问题，不招募参与者、不开展个人数据研究。外传前检查资料来源、保密性、许可与服务保留条件；界面勾选只是记录使用决定，不能代替合法使用依据。本阶段不外传工程图纸。

明确标注参考代码、论文和 AI 辅助，保留开发过程记录。生成内容不能未经核验当作标准答案，不将计划或目标写成既成结果。允许使用何种辅助方式，以适用的课程 assessment brief 为准。

学校的两个伦理选项保持未勾选，由学生与导师确认适用项；若未来增加参与者或个人数据，须在开展相应工作前确定审查要求。
