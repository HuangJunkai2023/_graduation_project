# Domain documentation

Use a single-context layout: root `GLOSSARY.md` and `docs/adr/`.

Before exploring domain concepts or making design decisions, read the glossary
if present and ADRs relevant to the affected area. If absent, proceed silently;
create terms or ADRs only when a real ambiguity or decision is resolved.

Use established glossary terms in tickets, code and research explanations.
Surface conflicts with existing ADRs before changing a decision.

The signed Proposal remains the research baseline. Consult `开题材料/README.md`
for the readable Proposal and `docs/progress_journal/WEEKLY_PLAN.md` for task
sequencing. Glossary entries, tickets and ADRs document decisions; they do not
establish experimental results, supervisor approval or journal publication.
