# 系统设计说明

本文件面向毕业设计论文的"系统设计"与"系统实现"章节，说明本文 RAG 系统的
总体架构、关键流程与算法细节，并把原工程中的进阶优化作为"可扩展方向"列出。

---

## 一、系统目标与需求

**问题**：铁路接触网相关的规范、标准、技术条件分散在大量 PDF / DOCX 中，
人工查阅效率低，且难以用自然语言提问、多轮追问、并追溯来源。

**目标**：构建一个面向规范文档的**检索增强问答（RAG）系统**，做到：

1. 支持 PDF / DOCX 文档入库，自动切块与向量化；
2. 支持自然语言提问，返回**基于文档**的答案；
3. 答案**附带引用来源**（文件名、页码、标准号），可人工核查；
4. 支持多轮追问；
5. 检索不到时能识别并**不硬答**（降低幻觉与误引用）。

**非目标（本期不做）**：多用户权限、分布式部署、复杂工作流编排。

---

## 二、总体架构

系统分为**离线建库**和**在线问答**两条链路：

```text
┌──────────────────────── 离线建库 ────────────────────────┐
│                                                          │
│  PDF / DOCX ─► 文档解析 ─► 文本清洗 ─► 元数据抽取         │
│        ─► 递归切块 ─► 在线 embedding 向量化 ─► 知识库文件  │
│                                                          │
└──────────────────────────────────────────────────────────┘

┌──────────────────────── 在线问答 ────────────────────────┐
│                                                          │
│  用户问题 ─► 闲聊判断 / 标准号抽取                        │
│        ─► 混合检索（向量 + BM25 融合）─► Top-K 证据       │
│        ─► 组装上下文与提示词 ─► 在线大模型生成            │
│        ─► 返回答案 + 来源 ─► 更新对话记忆                 │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**分层设计**（对应 `01_主要代码/`）：

| 层     | 模块                                         | 职责                           |
| ------ | -------------------------------------------- | ------------------------------ |
| 配置层 | `config.py`                                | 统一管理 API、切块、检索参数   |
| 服务层 | `online_api.py`                            | 封装在线 embedding / chat 接口 |
| 数据层 | `document_parser.py`、`text_splitter.py` | 解析、清洗、切块               |
| 检索层 | `vector_store.py`                          | 向量入库、BM25、混合检索融合   |
| 生成层 | `rag_pipeline.py`                          | 提示词、生成、记忆、兜底       |

> 之所以把"向量化"和"生成"统一封装到 `online_api.py`，是为了**解耦模型供应商**：
> 更换模型时只需改一处，检索与问答逻辑不受影响。

## 三、关键流程

### 3.1 文档预处理

1. **解析**：PDF 用 PyMuPDF 按页抽取文本；DOCX 抽取段落与表格（表格用制表符保留行列）。
2. **清洗**：去控制字符、全角空格；合并中文字符间被误插的空格
   （`接 触 网` → `接触网`）；压缩连续空行。
3. **元数据抽取**：从文件名/正文识别标准号（正则匹配 `TB/T`、`Q/CR`、`GB/T` 等），
   并归一化为紧凑形式（`TB/T 2075-2024` → `TBT20752024`），供检索过滤与来源展示。

### 3.2 文本切块

采用**递归字符切分**：按 `段落 → 换行 → 句号 → 分号 → 逗号 → 空格 → 字符`
的优先级递归切分，再合并为不超过 `CHUNK_SIZE` 的块，块间保留 `CHUNK_OVERLAP` 重叠。
兼顾"语义完整"与"长度可控"，避免切碎语义、也避免相邻块丢失上下文。

### 3.3 混合检索（核心）

对同一 query 同时执行两路互补检索：

**（1）稠密向量检索**——捕捉语义相似：

```
sim(q, d) = cos( E(q), E(d) )
```

其中 `E(·)` 为在线 embedding 接口。

**（2）稀疏 BM25 检索**——捕捉关键词精确匹配：

```
score(q,d) = Σ_t IDF(t) · [ f(t,d)·(k1+1) / ( f(t,d) + k1·(1-b+b·|d|/avgdl) ) ]
IDF(t)     = ln( 1 + (N - n(t) + 0.5) / (n(t) + 0.5) )
```

参数 `k1=1.5`、`b=0.75`。中文分词采用"单字 + 2/3 元 ngram + 英文数字整体"策略，
无需第三方分词器即可覆盖中文关键词匹配。

**（3）融合排序**——两路得分先各自线性归一化到 `[0,1]`，再加权求和：

```
fusion = VECTOR_WEIGHT · norm(向量分) + BM25_WEIGHT · norm(BM25分)
```

默认 `VECTOR_WEIGHT=0.6`、`BM25_WEIGHT=0.4`。
**只用一路会有明显短板**：纯向量检索对标准号、型号等"字面精确词"不敏感；
纯 BM25 又无法处理同义改写。二者融合可互补。

**（4）元数据过滤**：若问题中出现标准号，检索前按 `standard_no` 过滤候选集合，
提升"指定标准类问题"的命中稳定性（过滤命中不到时退回全集，避免空召回）。

### 3.4 生成与幻觉抑制

1. **上下文组装**：把 Top-K 证据拼成 `[来源n] 文件名 页码 ...` 的带标注上下文。
2. **提示词约束**：明确要求"只依据参考文档作答、无法确认要说明、标注 `[来源n]`"。
3. **兜底策略**：闲聊走通用回答不检索；检索为空回退通用回答，
   避免"强行引用无关文档"导致的错误引用。
4. **多轮记忆**：保留最近 N 轮问答用于理解追问中的指代（`MEMORY_ROUNDS`）。

## 四、可扩展方向

针对**规范类文可做**多项工程增强，
可作为论文的"系统优化"或"未来工作"部分：

| 优化点           | 解决的问题                 | 思路                                          |
| ---------------- | -------------------------- | --------------------------------------------- |
| 动态标准号过滤   | 支持任意标准号，不再硬编码 | 正则抽取`TB/T`、`Q/CR` 等并生成过滤 token |
| 目录页追踪正文   | 只召回目录、缺正文证据     | 识别目录页并从目录提取目标页码，补抓正文      |
| 章节质量重排     | 前言/术语片段权重过高      | 对技术要求类正文加权、对前言目录降权          |
| 对比类分标准召回 | 两个标准互相挤占 Top-K     | 按标准分组分别召回再合并                      |
| 动态词面召回     | 向量召回跑偏后无候选可救   | 从问题动态抽词做字符串包含召回                |
| 低置信度拦截     | 候选跑偏仍强行回答         | 本地字符串判断具体主体词是否命中              |
| 检索耗时打点     | 定位响应慢在检索还是生成   | 分阶段计时                                    |

**建议**：若论文篇幅或时间允许，选取其中 1–2 项（如"动态标准号过滤"+"对比类分标准召回"）
作为本文的改进点，并配合消融实验说明效果，能显著提升论文的工程含量。

## 五、主要参数一览

| 参数                                | 默认值      | 说明                       |
| ----------------------------------- | ----------- | -------------------------- |
| `CHUNK_SIZE`                      | 500         | 文本块长度                 |
| `CHUNK_OVERLAP`                   | 80          | 相邻块重叠长度             |
| `TOP_K`                           | 5           | 召回证据数                 |
| `BM25_WEIGHT` / `VECTOR_WEIGHT` | 0.4 / 0.6   | 融合权重                   |
| `EMBEDDING_MODEL`                 | embedding-3 | 在线向量模型               |
| `LLM_MODEL`                       | glm-4-flash | 在线生成模型               |
| `LLM_TEMPERATURE`                 | 0.3         | 生成温度（偏低以抑制发散） |
| `MEMORY_ROUNDS`                   | 5           | 多轮记忆轮数               |

## 六、运行环境

- 语言：Python 3.9+
- 依赖：`python-dotenv`、`zhipuai`、`numpy`、`pymupdf`、`python-docx`（网页演示另需 `streamlit`）
- **无需 GPU、无需本地模型**，仅需一个有效的在线 API Key
