# 研究材料核查指南

核查台是本机单人使用的研究工具，不会自动调用模型，不会把未审核题目记成已通过。

在工程根目录运行：

双击 `project/qa_system/start_review.cmd`，或使用下面的命令。核查台使用8502端口，演示问答页面使用8501端口。

```powershell
& ./project/qa_system/.venv-win/Scripts/python.exe -I -m streamlit run project/qa_system/review_app.py --server.address=127.0.0.1 --server.port=8502 --server.headless=true --browser.gatherUsageStats=false
```

打开 <http://127.0.0.1:8502>。默认使用独立研究数据库和候选题集，不覆盖演示知识库。

## 第一步：核查题目与原文

1. 左侧填写实际核查者姓名。默认查看开发集尚未通过的题目。
2. 先核查10道开发题，熟悉标准号、年份、位置、答案必要事实和可回答性的判断；再完成其余开发题与测试题。
3. 每题核对：问题是否明确；参考答案是否完整；数字、单位和适用条件是否保留；摘录是否连续且来自指定位置；版本是否符合请求。
4. 点击“显示PDF原文页”查看本机原文件。DOCX按页面显示的原路径打开，对照段落或表格行；不要只凭抽取文本确认。
5. 可修改问题、参考答案、必要事实和证据JSON。配额、分组或可回答性需要变化时，先标记“需要修订”，由题集维护流程调整后重新检查。
6. 明确选择“已对照原文，通过”或“需要修订”，填写必要说明后保存。每次决定保留姓名、时间和前后指纹。

可回答题需要1–3项必要事实及可追溯证据。不可回答题需要明确理由；“检索没有找到”本身不能证明语料中没有答案。缺版本、库外、无关及歧义题应分别判断。

不可回答题带有明确的 `unanswerable_type`：开发集四类各1题，测试集四类各4题。缺版年份只是用户请求，不能据此声称该年份的正式标准实际存在。若没有两个正式版本的真实材料，RQ2仅报告当前语料中已有版本／缺失请求版本的行为，不能推出真实版本变更辨析效果。

## 第二步：核查开发候选证据

20道开发题通过后，校准流程会生成三种检索方式的候选段落。切换“开发候选证据”，根据问题和原文判断每个候选是否支持所需事实，再保存“是”或“否”。

左侧“开发校准记录”默认选择 `runtime/research/calibration/v1/selection_prepared.json`，与执行说明中的prepare命令一致；如使用新校准版本，选择对应记录，页面从记录中读取准确的标签文件。开发题或语料改变后会阻止使用旧标签。新正式实验版本也应在左侧选择相应结果目录和独立盲评记录，保留旧版记录。

- 同一问题／同一文本块只需核查一次。
- 自动提出的相关性不会自动计为人工判断。
- 非gold段落也可能提供有效支持；不能一律当成负例。
- 只提到相同术语但不支持所问结论的段落，应与有实际支持的段落区分。

权重、Gate阈值只使用开发集选择。测试输出不得用于选择参数或改题。

## 第三步：冻结与正式运行

“冻结就绪情况”展示题目配额、证据摘录和审核记录是否齐全。全部100题通过后，还必须满足开发校准、语料向量、模型与配置一致性，才可由冻结接口生成不可覆盖的新版本快照。

快照包含题集、语料、配置、提示词和代码指纹。发生变化需新建版本，不覆盖旧结果。当前界面不会自动冻结，也不会自行启动400次正式运行。

## 第四步：正式输出盲评

正式运行结束后切换“正式结果盲评”。页面隐藏B1/B2/B3/A1/A2及运行文件名；核对问题、参考事实、系统答案和来源后判断：

判分使用每次运行保存的冻结题目快照。当前可编辑候选题不能替代冻结gold；缺少该快照的旧记录不能直接保存为正式评分。页面只读取五组预定配置文件，不把日志或盲评任务导出文件当作额外实验。

- 回答是否完全正确；是否用错版本；是否合理拒答或误拒答；
- 每一条已展示的事实断言，是否得到其整组引用的共同支持；
- 主要失败类型及核查依据。

完全相同的答案、claims和证据集合会合并一次判断，仍保留所有运行槽位映射。答案相同但证据不同不会合并。没有人工决定的评分不自动补零或补通过。

## 保存位置与限制

- 候选题：`project/qa_system/runtime/research/benchmark/candidates.jsonl`
- 审核历史：候选题旁的 `.reviews.jsonl` 文件；候选证据标签旁也保存自己的审核历史。
- 正式结果：`project/qa_system/runtime/research/results/`
- 盲评分数：`project/qa_system/runtime/research/scoring/grades.jsonl`

这些文件可能含标准摘录和测试答案，只保存在本机受控目录。不要将API密钥、完整标准或未公开测试答案放入公共仓库。文档与研究结论的人工核查不能由“软件检查通过”代替。
